# Gallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A producer console where AI agents propose verified, explainable match insights from a synthetic football match, a human approves them to air, and approved items fan out to personalized fan feeds, all audited.

**Architecture:** One Python FastAPI service. A seeded simulator feeds a deterministic stats engine and moment detectors; an Agent Framework crew turns moments into verified proposals; a match runtime owns the clock, the proposal queue and the audit log, and pushes state to a vanilla-JS console over WebSocket.

**Tech Stack:** Python 3.11, pydantic v2, FastAPI, uvicorn, agent-framework-core + agent-framework-openai (`OpenAIChatCompletionClient`), SQLite (stdlib), pytest + pytest-asyncio, vanilla JS + canvas, Docker, Azure Container Apps, Microsoft Foundry.

**Spec:** `docs/superpowers/specs/2026-10-25-gallery-design.md`

## Global Constraints

- Python venv lives at `C:\Users\sreer\.venvs\gallery` (the session folder path is too long for some DLLs). Run Python as `/c/Users/sreer/.venvs/gallery/Scripts/python` (alias `$PY` below).
- Synthetic data only: fictional clubs `Northgate FC` (NOR) and `Harbour Athletic` (HAR); no real club, player or league names anywhere, including UI copy.
- No number, name or minute reaches on-air output unless the verifier passed it or a template produced it.
- `GALLERY_PROVIDER` in {`github`, `foundry`, `replay`}; missing credentials fall back to `replay` with a warning.
- LLM timeout 8 s, one retry, then template fallback.
- Default proposal shelf life 120 match-seconds. Auto-approve only applies to kinds `player_tag` and `speed`.
- Languages: `en`, `es`. Fan variants: `casual`, `analyst`, `player`, `es`.
- Speed factors: 1, 15, 30. Match is 90 match-minutes, two halves of 45.
- Same seed must produce an identical event list.

## Review Focus

- Producer acts on a proposal that already expired or was already acted on: return 409, never air twice. Test in Task 8.
- LLM returns JSON wrapped in ```json fences, extra prose, or invalid JSON: strip fences, else count as a failed attempt and fall back. Test in Task 6.
- Producer edits text to contain a wrong number: verifier re-runs on the edit; airing is still allowed but logged as `override` with the errors. Test in Task 8.
- Console reconnects or a second tab opens mid-match: receives a full snapshot and stays consistent. Test in Task 9.
- Restart match / change speed mid-match: old loop is cancelled, state reset, no duplicate events. Test in Task 8.

### Task 2: Match simulator

**Files:**
- Create: `gallery/sim/__init__.py`, `gallery/sim/squads.py`, `gallery/sim/engine.py`
- Test: `tests/test_sim.py`

**Interfaces:**
- Consumes: `Event`, `Player`.
- Produces: `squads.SQUADS: dict[str, list[Player]]` (11 starters + 3 subs per team, fictional names, ids like `NOR-9`); `engine.simulate(seed: int) -> list[Event]` returning the whole match sorted by `t` (0..5400 plus stoppage), ids sequential from 1.

Approach: possession-chain state machine. Each chain: a few passes/carries advancing toward goal with probabilities depending on zone and a team "press" parameter; ends in shot, tackle, interception or out of play. Emit `pressure` events on the receiver at a rate scaled by the defending team's press level, `sprint` events with `speed_kmh` 24-35, shots with `speed_kmh` 60-120. Script story beats by seed via a press/attack intensity schedule: NOR high press 55'-63', HAR momentum 70'-78', one NOR player reaches 50 completed passes, at least two goals. Use `random.Random(seed)` only.

### Task 3: Stats engine

**Files:**
- Create: `gallery/stats/__init__.py`, `gallery/stats/engine.py`
- Test: `tests/test_stats.py`

**Interfaces:**
- Produces: `class StatsEngine` with `ingest(e: Event) -> None`, `team(code: str) -> dict`, `player(pid: str) -> dict`, `window(team: str, t0: float, t1: float) -> dict`, `snapshot() -> dict`, and `events: list[Event]`.
  - team dict keys: `goals, possession_pct, passes, pass_accuracy_pct, shots, shots_on_target, pressures, pressures_per_min_opp_half, momentum, control_chaos` (0 = control, 100 = chaos).
  - player dict keys: `name, team, passes, passes_completed, pass_accuracy_pct, avg_pass_m, avg_pass_difficulty, top_speed_kmh, distance_km, shots, top_shot_kmh`.
  - window dict: same team keys computed over `[t0, t1)`.
- Formulas (fix these exactly): pass distance = euclidean (x,y)->(end_x,end_y); pass difficulty 1-10 = `clamp(1 + dist/8 + 2*under_pressure + 1.5*(forward progression > 15m), 1, 10)` rounded to 1 dp; possession % by time between possession_change events; momentum = sum over last 300 s of (shot 3, big chance 5, final-third entry 1) with linear decay, scaled 0-100 and normalized between the two teams; control_chaos = `clamp(100 * turnovers_per_min / 4 * (1 - pass_accuracy/100 + 0.5), 0, 100)` over last 300 s. Round percentages to integers.

- [ ] **Step 2: Run** -> FAIL. **Step 3: Implement.** **Step 4: Run** -> PASS. **Commit** `feat: deterministic stats engine`.

### Task 6: LLM layer with replay cache

**Files:**
- Create: `gallery/llm.py`
- Test: `tests/test_llm.py`

**Interfaces:**
- Produces:
  - `class LLM(Protocol)`: `async def run(self, agent: str, instructions: str, prompt: str, tools: list[Callable] = []) -> str`.
  - `class AFLLM(LLM)`: wraps Agent Framework. Builds `OpenAIChatCompletionClient` once: `github` -> `base_url="https://models.github.ai/inference"`, `api_key=github_token`, `model=github_model`; `foundry` -> `azure_endpoint=foundry_endpoint`, `api_key=foundry_key`, `model=foundry_deployment`. `run` creates `Agent(client, instructions, name=agent, tools=tools)` and returns `(await agent.run(prompt)).text`, wrapped in `asyncio.wait_for(..., 8)`.
  - `class ReplayLLM(LLM)`: `__init__(inner: LLM | None, cache_dir: Path, record: bool)`; key = sha256 of `agent|instructions|prompt`; hit -> cached text; miss and `inner` -> call, store if `record`; miss and no inner -> raise `ReplayMiss`.
  - `AFLLM.status: Literal["ok","degraded"]` set to `degraded` for 60 s after a 429 (calls during that time raise immediately so the crew uses templates); surfaced in the runtime snapshot as `provider_status` and drawn as an amber provider badge.
  - `make_llm(settings) -> LLM`: `replay` -> `ReplayLLM(None, ...)`; others -> `ReplayLLM(AFLLM(...), ..., record=True)` so every live run fills the cache.
  - `parse_json(text: str) -> dict` (strips ```json fences and leading/trailing prose up to the outermost braces; raises `ValueError` otherwise).
  - `class FakeLLM(LLM)` in `tests/fakes.py`: returns queued responses or raises queued exceptions; records calls.

### Task 8: Audit log and match runtime

**Files:**
- Create: `gallery/audit.py`, `gallery/runtime.py`
- Test: `tests/test_runtime.py`

**Interfaces:**
- Produces:
  - `class Audit`: `__init__(db_path: str)`, `log(kind: str, t: float, proposal_id: str | None, data: dict) -> dict` (returns the row incl. wall-clock `ts`), `all(match_id: str | None = None) -> list[dict]`. Kinds: `moment, agent_step, verify, proposed, approved, edited, override, rejected, expired, aired, recap`.
  - `class MatchRuntime`: `__init__(crew_factory, audit: Audit, broadcast: Callable[[dict], Awaitable[None]])`; `async start(seed: int, speed: int)` (cancels any running loop, resets stats/queue, new `match_id`); `set_speed(speed: int)`; `async approve(pid: str, edited_text: str | None = None) -> Proposal`; `async reject(pid: str, reason: str) -> Proposal`; `set_auto_approve(on: bool)`; `snapshot() -> dict` (`match_id, t, speed, score, team stats, proposals, on_air, recaps, provider, auto_approve`).
  - Loop: advance match clock by `0.25 * speed` match-seconds every 0.25 s wall; ingest due events; run detectors; spawn `crew.propose` tasks (max 3 concurrent, drop lowest priority if more); expire pending past `expires_at`; at 45' and 90' request recap; broadcast messages `{"type": "tick"|"proposal"|"proposal_update"|"on_air"|"audit"|"recap", ...}`; tick at most 4 per wall second.
  - Approve/reject on non-pending -> raise `Conflict`. Approve with `edited_text` runs `verify_text`; errors -> log `override` with errors and still air. Approve triggers `crew.personalize` in background, then broadcast `proposal_update` with variants.
